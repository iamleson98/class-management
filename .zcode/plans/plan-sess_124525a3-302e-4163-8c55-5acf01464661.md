### Part C — Make error states consistent (red border + label + subtext)

The infrastructure already exists. The fixes target places that bypass it:

1. **`date-picker.tsx` / `time-picker.tsx`**: forward `aria-invalid` to the trigger so it turns red.

2. **`schedule.tsx` dialogs** (create/edit session): these use raw `<Label>` + `<Select>`/`<Input>` + manual `form.register`/`setValue`, so `aria-invalid` is never set on the controls.
   - For each field, pass `aria-invalid={!!form.formState.errors.<field>}` to the `<Select>`/`<Input>`/`<DatePicker>`/`<TimePicker>` trigger.
   - Make the `<Label>` turn red by adding `data-error={!!form.formState.errors.<field>}` + `className="data-[error=true]:text-destructive"` (mirroring what `FormLabel` does internally), OR convert these rows to use `FormField`/`FormLabel`/`FormControl` (cleaner, but larger change). I'll use the lighter `aria-invalid`/`data-error` approach to minimize churn.
   - The error `<p>` subtext is already red (`text-destructive`) ✅.

3. **All `FormMessage` usages already render red** ✅ — no change needed across the 13 form files for label/subtext; they already work via `FormLabel`/`FormMessage`.
