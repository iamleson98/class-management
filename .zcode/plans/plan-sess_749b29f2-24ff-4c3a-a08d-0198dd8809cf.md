# Add `NEXT_PUBLIC_API_URL` env var to replace Next.js proxy

## Current state
- All API calls use relative paths (`/api/v4/lms`, `/api/v4/users/me`) that are proxied via Next.js `rewrites()` to `http://localhost:8065`
- No `NEXT_PUBLIC_*` env vars exist
- `.env` has only server-side vars (database, JWT, SMTP)

## Changes

### 1. Update `.env` — add `NEXT_PUBLIC_API_URL`
```
NEXT_PUBLIC_API_URL=http://localhost:8065
```
Also update `.env.example` with a template.

### 2. Update `next.config.ts` — remove `rewrites()`
Remove the `rewrites()` async function that proxies `/api/v4/:path*` → `http://localhost:8065/api/v4/:path*`. No longer needed since the frontend will call the backend directly.

### 3. Update `src/lib/api.ts` — use env var as base URL
- Change `BASE` from `'/api/v4/lms'` to use the full URL from env: `` `${process.env.NEXT_PUBLIC_API_URL}/api/v4/lms` ``
- Change `PUBLIC_BASE` similarly
- Change `getMe()` path from `'/api/v4/users/me'` to use full URL
- Change `logout()` path similarly
- Change `loginWithMattermost()` path similarly
- Add a helper like:
  ```typescript
  const API_URL = process.env.NEXT_PUBLIC_API_URL || 'http://localhost:8065'
  ```

### 4. Update `src/lib/file-upload.ts`
Change `/api/v4/uploads/` to use the full URL from env.

### 5. Update `src/lib/sitemap.ts` (if it calls any API — it uses `APP_URL` which is fine)

### Files modified:
1. `lms-fe/.env` — add `NEXT_PUBLIC_API_URL`
2. `lms-fe/.env.example` — add template
3. `lms-fe/next.config.ts` — remove rewrites
4. `lms-fe/src/lib/api.ts` — use `NEXT_PUBLIC_API_URL` for all endpoints
5. `lms-fe/src/lib/file-upload.ts` — use `NEXT_PUBLIC_API_URL`

### Note on cookies
Since the frontend (port 3001) will now call the backend (port 8065) directly (cross-origin), the `credentials: 'same-origin'` in fetch calls needs to change to `credentials: 'include'` so cookies are sent cross-origin. The Go backend will also need CORS headers allowing the frontend origin — check if that's already configured.
