## Prerequisite — Fix the role-casing bug (so students are actually visible)

The student list query filters `users.roles LIKE '%lms_student%'`, but the two places that create students write the UPPERCASE string `"STUDENT"`. Today, students created via the API never appear in the student list.

- **`server/channels/app/lms/student.go:51`** — change `user.Roles = "STUDENT"` → `user.Roles = model.RoleLmsStudentRoleId`.
- **`server/channels/app/lms/lead.go:95`** — change `Roles: "STUDENT"` → `Roles: model.RoleLmsStudentRoleId`.
- Leave `dashboard.go:50-66` alone (it switches on a query-param label, not the stored roles string).
- Leave the frontend `normalizeRolesString` map (`api.ts:295-304`) in place — it's harmless once the backend writes lowercase, and keeps backward compat with any legacy uppercase rows.

## Feature 3 — Counselor can convert user ↔ student

You confirmed UI lives **inside Counselor CRM**. Counselors have `lms_manage_students` but NOT `lms_manage_users`, so the user-listing-for-conversion must be gated by `lms_manage_students`.

### Backend

- **`server/channels/app/lms/student.go`** — add:
  - `GetConvertibleUsers()` — returns users whose roles do NOT contain `lms_student` (i.e. normal/staff users eligible to become students), excluding deactivated.
  - `ConvertUserToStudent(userID)` — load user, set `Roles = model.RoleLmsStudentRoleId` (+ keep `system_user`), preserve existing password/props, save via `store.User().Update(nil, user, true)`. (Distinct from `CreateStudent`, which creates a brand-new row with a default password.)
  - `RevertStudentToUser(studentID)` — load user, set `Roles = model.SystemUserRoleId`, clear the `"student"` props key, save.
- **`server/channels/api4/lms_api/student.go`** — add three handlers, all gated by `PermissionLmsManageStudents`, wired in `InitStudents`:
  - `GET  /lms/students/convertible-users` → `GetConvertibleUsers`.
  - `POST /lms/users/{user_id}/convert-to-student` (registered under the students init for permission cohesion) → `ConvertUserToStudent`.
  - `POST /lms/students/{id}/revert-to-user` → `RevertStudentToUser`.

### Frontend

- **`lms-fe/src/lib/api.ts`** — add `getConvertibleUsers()`, `convertUserToStudent(userId)`, `revertStudentToUser(studentId)`.
- **`lms-fe/src/components/lms/counselor/crm.tsx`** — convert the page to a **two-tab layout**: `Leads` (the existing content, untouched) and a new `Convert` tab. The Convert tab shows:
  - **"Convertible users"** list (from `getConvertibleUsers`) with a **"Chuyển thành học viên"** button per row → `convertUserToStudent`.
  - **"Students"** list (from `getStudents`) with a **"Chuyển về người dùng"** button per row → `revertStudentToUser`.
  - Both invalidate `['students']` + `['convertible-users']` on success and toast.
  - Add i18n keys to `lms-fe/src/lib/i18n/locales/{en,vi}.ts`.

## Feature 4 — Remove the `__all__` filter leak

Backend already treats empty `where_ands`/`where_ors` as match-all (`query.go:179-183` → clause `TRUE`), and `query.ts` `build()`/`and()`/`or()` already drop empty-string values. Radix Select **forbids empty-string item values**, so a UI sentinel is unavoidable — `reviews.tsx`/`courses.tsx` already handle it correctly by converting `__all__ → ''` in `onValueChange`. **Only `homework.tsx` is broken.**

- **`lms-fe/src/components/lms/admin/homework.tsx:349`** — change
  `setFilterClassId(v)` → `setFilterClassId(v === '__all__' ? '' : v)`, matching `reviews.tsx:272`. This makes "Tất cả lớp" actually return all classes instead of querying `homeworks.class_id = '__all__'` (which matches nothing).
- No changes to `reviews.tsx`, `courses.tsx`, the query builder, or the backend — they're already correct.
